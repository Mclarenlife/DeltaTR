# MOZA KS Pro 方向盘屏显（实验功能）

DeltaTR 0.14.0 为 KS Pro 的 780×248 屏幕提供居中对称声波与中央文字，替代此前的三角形和侧边气泡。沿用软件的讲话键、语音识别、自定义词库、唤醒词和 AI 设置。保留 Pit House 实验共存桥接及独立串口连接。

## 保留 Pit House（实验共存）

1. 保留完整发布目录，启动新版 DeltaTR，选择游戏后连接真实遥测或启动演示。安装、升级和重启 Pit House 时请先退出驾驶会话。
2. 在 DeltaTR「屏显」选择「保留 Pit House · 实验共存」。已开启方向盘屏显时先关闭，再点「安装 / 升级桥接」。程序支持已验证的 Pit House 1.4.2.3，会校验并备份界面和遥测定义文件。
3. 重启 Pit House，等待 KS Pro 设备连接，让新版五行文字字段生效。
4. 导入本次发布的 `DeltaTR KS Pro.mzdash`，保留同级 `Resource` 目录，把 `DeltaTR KS Pro Fullscreen Radio` 上传到方向盘。
5. 在 Pit House 选回日常比赛仪表，再在 DeltaTR 点击「开启方向盘屏显」。
6. 在无线电中输入问题或按原有讲话键，回答会通过本机桥接显示在 KS Pro。状态「Pit House 已接收屏显消息」表示内部方法返回确认，不是物理屏幕回读。

当前桥接使用 `DeltaTRRadio` 至 `DeltaTRRadio5` 五个专用字符串字段，不再占用车手姓名。检测到游戏进程时不再暂停文字写入。iRacing 单人练习座舱、维修区停车状态下已实测中文递增、停止重复写入后保持 30 秒、游戏转速与设备状态同时正常。ACC / LMU 的显示共存、长时间驾驶、所有灯效和力反馈效果仍待实测。

服务只接受新版支持切换的专用字段客户端，旧版尚未重启的 Pit House 会被拒绝并显示升级提示。新版客户端也拒绝旧版 DeltaTR 服务。安装状态同时检查 QML 与遥测定义；只安装一部分时不能开启。自动切换通过设备内仪表列表识别唯一的 `DeltaTR KS Pro Fullscreen Radio`；缺失或重名时会提示，不猜测编号。服务端接收确认不是屏幕内容回读。

关闭屏显、切换游戏、退出 DeltaTR 时停止服务，接收端在失联/消息过期后最多约三秒释放显示；关闭智能切换时，待命保留声波、隐藏中央对话文字；开启智能切换时，自动消息结束后返回原比赛仪表。桥接未曾收到消息时不写屏幕。

卸载：点击「恢复 Pit House 原文件」，再重启 Pit House。备份与安装清单位于 `%LOCALAPPDATA%/DeltaTR/MozaBridge`；恢复时先校验全部文件与备份，再将两份文件恢复为安装前的原始内容；安装或恢复中途退出可以重新恢复。安装后文件被其他程序改变时拒绝覆盖。更新 Pit House 后需要重新验证版本。工具入口为 `tools/MozaBridgeSetup`，与界面共用相同安装器。

实现使用 127.0.0.1:17895、随机本机访问凭据与有期限的消息；不监听外部地址，不发送音频、API 密钥或历史对话，只提供当前一页文字。端口被占用时显示启动错误。消息接收端只调用固定文字字段，不执行网络传来的脚本或方法名。

## 短按、长按与自动弹出

「屏显」新增「智能仪表切换」和「赛事提醒和自动化播报临时弹出」开关。键位共用设置中的讲话键，支持键盘与方向盘按钮，不另抢占串口。智能切换仅在 Pit House 共存屏显运行时生效，关闭后保持原来的按住即开始讲话。

- 短按（少于 0.5 秒）松开：显示 DeltaTR；再次短按：返回切换前的比赛仪表。
- 长按达到 0.5 秒：打开并保持 DeltaTR，开始采集语音；松开后发送，不再触发一次短按切换。看到输入提示后讲话。
- 黄旗、排名变化、处罚和自动化结果沿用现有播报配置与队列，只在消息实际展示时弹出。等待语音播报及文字阅读/翻页时间结束再返回；连续消息保持画面，避免来回闪动。
- 手动打开或长按进入的 DeltaTR 保持显示，直到再次短按；不会因某条自动消息结束被切走。
- 自动消息显示期间短按可提前关闭当前消息的画面；下一条新消息仍可弹出。
- 切换由 Pit House 自身接口完成，记录原仪表标识而非固定列表位置。手动在 Pit House / 方向盘切换到别的仪表时会让出控制，不反复抢回当前消息。
- 关闭屏显、切换游戏、退出 DeltaTR 或消息租期过期时，尝试恢复由本次会话临时替换的仪表。设备掉线、原仪表被删除、多个 KS Pro 或缺少目标仪表时不猜测目标，显示原因。

首次开启时若已经处于 DeltaTR 仪表，请先在 Pit House 选择要返回的比赛仪表。从旧版桥接升级到 0.14.0 时按上方步骤更新桥接与仪表。已使用 0.14.0 全屏仪表时，本次动画更新只需更换方向盘上的仪表。导入时保留同级 Resource 文件夹，上传后确保轮上只有一份名为 `DeltaTR KS Pro Fullscreen Radio` 的仪表，再选回日常比赛仪表。

## 独立连接（原有模式）

1. 在 DeltaTR 选择游戏，打开「屏显 → KS Pro 方向盘屏幕」。点击「打开仪表文件夹」。
2. 在 Pit House 的 KS Pro「仪表盘设置」中导入文件夹内的 `DeltaTR KS Pro.mzdash`，将其上传至方向盘，并在设备仪表列表选中应用。保留同级 `Resource` 文件夹。
3. 退出 Pit House，回到 DeltaTR，选择「独立连接 · 需退出 Pit House」，选择检测到的 MOZA 基座并点击「开启方向盘屏显」。首次接管需约 15–35 秒。
4. 连接游戏或启动演示，按住已绑定的键/方向盘按钮讲话，松开发送。也可在无线电页面输入文字提问。
5. 使用完点击「关闭方向盘屏显」，再打开 Pit House；可在其设备仪表列表切回原来的比赛仪表。

两种模式默认都不自动开启。独立模式下，Pit House 占用串口时显示明确提示，不会强制关闭其他软件。

## 显示行为

| 状态 | 屏幕表现 |
| --- | --- |
| 游戏未连接 | 暗色声波，中央显示「未连接游戏」 |
| 已连接且待命 | 对称声波缓慢起伏，从中央的雾紫色渐变到两端的冰蓝色，中央无对话文字 |
| 按住讲话 | 淡粉、紫色和冰蓝柔光沿圆角边缘顺时针流转，每 5.76 秒一圈，向屏内渐隐。中央声波变暗并显示输入文字。松键后光晕消失，四角仍保留圆弧遮罩。 |
| 处理语音或等待 AI | 保留暗色声波与输入文字；确认结果短暂停留后进入回答 |
| 工程师回答 / 主动广播 | 中央显示中文回答，声波保持低亮度，全屏上下左右居中，超出五行后每八秒翻页 |

输入预览使用本机 Zipformer 流式识别，共用当前麦克风采样，不重复打开麦克风。即使最终引擎选择 SenseVoice 或 Windows，也只用 Zipformer 生成屏幕草稿，松键后的最终识别仍由设置中的引擎执行。草稿不会触发遥测查询或 AI 请求；取消输入后丢弃迟到结果。缺少 Zipformer 模型时显示「请讲话」，最终识别完成后才显示确认文字。并行预览会增加模型内存占用，首次加载可能稍慢。

五行分别传输，每行均遵守 127 个 UTF-8 字节的限制。普通中文每行最多 24 个字，一屏最多 120 字，显式换行会占一行；屏显最多处理前 4000 个 Unicode 字符，完整回答保留在桌面无线电页。分页显示时间至少覆盖一轮内容。实时遥测问答仍随数据刷新，不会因每次数值变化重置到第一页。新问题、状态改变会从第一页开始。进入仪表时，中央底图与声波首帧一致。声波采用 48 帧、每帧 60 毫秒的本地循环，切换录音、回答或翻页时持续播放。输入灯带由独立图层显示。

桌面屏显的文字位置、大小与透明度控制仅作用于桌面悬浮窗，KS Pro 当前使用固定的 780×248 布局。

## 实现位置与参考

最新进展（2026-11-10）：专用字段已在 iRacing 维修区与真实遥测共存验证通过，0.13.3 已接入同一字段，并增加旧桥接升级和双文件恢复。详见 [内部桥接研究](MOZA_INTERNAL_BRIDGE_RESEARCH.md)。以下保留此前各阶段记录，按阶段时间理解，不代表当前实现仍使用姓名字段。

### Pit House 共存调查（2026-11-10）

用户要求正式使用时保留 Pit House 的功能。当前独占串口实现只作为屏幕能力验证，不能视为满足这个要求的正式方案。保留连接冲突检查，不能通过去掉检查来实现共存。

已检查本机 MOZA SDK 1.0.1.8 的 `mozaAPI.h`：显示相关接口包括单位、亮度、仪表列表和当前仪表切换，未找到任意文字/自定义遥测写入接口。MOZA 官方在 [自定义游戏遥测接口答复](https://support.mozaracing.com/en/support/discussions/topics/70000509459/page/last)中说明 SDK 暂不直接支持遥测接入，需要由其开发团队适配。Dash Studio 文档的 JavaScript 表达式功能不能作为支持网络请求或第三方数据注入的证据。

另检查了 [AZOM 的 Pit House UDP 接口研究](https://github.com/giantorth/AZOM/blob/main/docs/protocol/pithouse-udp/README.md)：已记录的操作是方向盘转角参数读写，没有据此确认屏幕文字写入能力。AZOM 接管设备的路线也不满足继续使用 Pit House 的要求。

待验证的共存架构是 DeltaTR → Pit House 可接受的扩展/数据入口 → KS Pro，由 Pit House 保持设备连接；尚未找到并实测这一入口。内部桥接只能作为研究方向，不能标记为已支持。验收必须同时确认实际游戏遥测、原有灯效/踏板效果、设备设置、语音中文显示以及连接恢复。此次调查没有改写 Pit House 文件、安装串口代理或发送未知设备控制指令。

### 本机入口验证结果（2026-11-10 15:32，亚洲/上海）

结论：**本机共存通信验证通过，中文写入入口未验证通过。** 没有据此启用或宣称支持共存屏显。

| 检查对象 | 实际观察 | 对中文屏显的意义 |
| --- | --- | --- |
| Pit House 1.4.2.3 的 UDP 40288 | 已发送已知 PacketId 4 读请求，基座重连后返回两个转角字段，均为 540° | 能在保留 Pit House 时读设备配置；不是任意文字接口 |
| Racing Lab 的本机 WebSocket 17890 `/control/main` | `ai.status` 返回有效结果，包含 control、inference、modelReady 等字段 | 本机桥接可通信；检查到的方法目录未提供显示文字/自定义遥测写入 |
| Pit House 与 Racing Lab 的内部通信 | 本机日志确认动态 PUB/RPC 端口；进程中存在遥测发布与控制消息类型 | 仅证明内部通信存在，没有把它推断为第三方写入入口 |
| 内部 `TestSendTelemetryData` | 本地资源显示其 UI 为批量遥测压力测试开关与发送间隔 | 未启用；不是已确认的单条文字扩展接口 |
| 官方 SDK 1.0.1.8 / Dash Studio 绑定 | 与前次检查一致，未找到对外的任意文本写入方法 | 当前不能使用这些接口完成共存中文显示 |

最初设备查询返回未连接/参数错误；同一时段 Pit House 日志报告 COM3 拒绝访问。用户关闭 DeltaTR 的独占方向盘屏显后，Pit House 恢复设备通信，同一个读请求返回有效转角字段。可确认是独占连接冲突，不能通过取消 DeltaTR 的进程检查解决。

Racing Lab 查询使用的是官方客户端已有的控制连接。观察到连接关闭附近其自身日志出现释放踏板 AI 接管的动作（`enabled=false`）；尚不能仅凭时间相关性认定因果，也不能保证该通道完全不影响其辅助驾驶会话。因此测试工具默认只检查 Pit House 的 UDP 读接口，Racing Lab 检查需显式 `-ProbeRacingLab`，不应在启用驾驶辅助时运行。DeltaTR 没有发送任何踏板或力反馈设置指令。

检查工具位于 `tools/MozaScreenProbe/`：`Test-PitHouseReadOnly.ps1` 用于本机读查询，其余 `Inspect-*.py` 只读分析安装文件，研究产物保存在 `artifacts/moza-coexist/`，不随应用发布。最终设备已连接的响应见 `read-only-connected.json`。没有修改 Pit House 安装文件或设备参数，没有发送测试中文，也没有启用实验开关；Pit House 保持运行，DeltaTR 的独占方向盘屏显由用户关闭。
