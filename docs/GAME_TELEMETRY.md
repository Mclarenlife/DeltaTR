# 游戏数据源（0.12.0）

| 游戏 | 本机接口 | 主要可查询项目 |
|---|---|---|
| Assetto Corsa Competizione | Physics、Graphics、Static 共享内存及本机赛事广播 | 详见 ACC 字段核验矩阵 |
| Le Mans Ultimate | LMU_Data（原生 Windows x64，pack 4） | 车速、油量、转速、挡位、水温、胎体温度、当前胎压、刹车温度、排名、已完成圈数、上一圈、同圈前车时间差、气温、路温、剩余时间、进站状态 |
| iRacing | Local\\IRSDKMemMapFileName（按 SDK 变量描述表读取） | 车速、油量、转速、挡位、水温、排名、圈数、上一圈、剩余时间、气温、路温、维修区状态、各轮冷胎压设定、上次测量的中部胎体温度与剩余胎面比例 |

LMU 的热胎压与 iRacing 的冷胎压设定在无线电中均以 psi 报告。LMU 胎体温度从 K 换算成 °C；iRacing 的轮胎报告有独立问法。车型、会话未提供变量或单位不匹配时，不生成数值回答。iRacing 通用词库不会将冷胎压当作热胎压，也不使用 ACC 广播；原始压力通道仅在当前会话确实公布时读取。

LMU 对齐玩家遥测槽和计时表里的车辆 ID；物理与计时分别检查更新时间。参考 [Studio 397 接口的 ctypes 布局映射](https://github.com/TinyPedal/pyLMUSharedMemory/blob/e9b71b65e52a67488eecf70505112ea2921f3b46/lmu_data.py)，本版使用车辆物理记录 1888 字节、计时记录 584 字节的布局。游戏厂商更新结构后需要重新核验。

iRacing 按类型和单位检查变量，复制最新的完整缓冲区，用会话 YAML 确定赛道和玩家车型。参考 [iRacing SDK 内存结构](https://github.com/vipoo/irsdk/blob/master/irsdk_defines.h) 和 [iRacing 轮胎报告说明](https://support.iracing.com/support/solutions/articles/31000167257-black-box-screen-information-and-controls)。均以只读方式打开现有映射。启动游戏并进入可驾驶会话后自动检测。

## 扩展词库和赛事播报

LMU 按上述固定版本的物理、车轮、单车计时、赛段和公共接口结构提供 648 个查询项目，含本车与全场视角、四轮拆分和汇总问法。本车物理包括混动电量、虚拟能量、回收功率、制动及轮胎；计时包括分段、车手、旗语、处罚、进站次数和车距。全场物理只组合能按车辆编号与当期计时表对齐且时间接近玩家帧的数据。轮胎磨耗字段沿用 SDK 原始比例，未换算成可用圈数。指针、保留位、安装路径、账号及网络地址排除在无线电词库之外。

iRacing 离线提供 795 个参考查询项目：483 个新旧变量参考、256 条会话资料路径、27 个本车数组查询及 29 个通用/赛事查询。完整变量名、类型、单位、会话路径、Data API 参考端点及可用性限制见 [iRacing 数据清单](IRACING_DATA_INVENTORY.md)。参考库包含磁盘专用字段，不等于这些项目全部实时可用。连接后使用游戏当前发布的变量描述表，包括未知的新变量、位掩码、字符串和数组（保留 SDK 索引）。会话 YAML 中的资料按路径加入词库，重复条目显示序号。本地查询可读取报名资料、成绩和车手姓名，排除口令、用户账号 ID；扩展帧和名单不写入诊断录制或自动上传给 AI。仅写入磁盘日志的通道没有实时数据。不同赛车、会话的实际项目数可能不同，游戏重新提供字段时恢复该字段保存的问法。

两款游戏的「赛事播报」使用本机计时数据。可问“前车是谁”“后车是谁”“谁在领跑”“比赛排名表”“现在是什么旗”。相邻车按总排名判断，以玩家车辆 ID 或 CarIdx 为基准；缺少相邻名次、排名有歧义、计时过期或没有有效驾驶数据时不报告相应车手。ACC 的对手车手和排名资料使用独立的 UDP 广播接口。

主动提醒使用本机驾驶数据。ACC 读取本车旗语、全场及三个赛段的黄旗、处罚代码和总排名。LMU 读取全场黄旗和安全车阶段、本车未执行处罚的数量和总排名，数量增加时播报新处罚。iRacing 读取黄旗与警戒旗、本车黑旗或取消资格标记和总排名。接口只提供当前处罚状态，相同状态之间发生的多次判罚可能无法区分。

## 自动化与对手速度

排名提醒优先使用能匹配本车 ID 的新鲜赛事排名，再回退到本车排名字段。单次读数缺失会暂时保留比较基准。新名次需要连续更新的数据确认，排队期间再次变更时合并为最新结果。换位对象通过变化前后的车辆 ID 和排名确认，进站或多人换位无法唯一确认时只报告名次。

ACC 对手速度来自 UDP 车辆帧的 km/h，LMU 来自计时表局部速度向量的长度。iRacing 未提供对手瞬时速度的通用实时通道，使用约半秒内的圈进度和赛道长度计算并标为估计值，过期、进站和位置跳变时丢弃估算。

LMU 头车秒差来自 mTimeBehindLeader，iRacing 正赛秒差来自 CarIdxF2Time。有圈差时报告圈差。ACC 在积累有效广播轨迹后，用对手经过本车当前位置的时间估算秒差，并播报“估计”。资料不足时明确说明秒差暂不可用。比赛开始采用已观察到的开赛前状态到比赛阶段的转换，重连和中途进入比赛不会补发开始事件。ACC 优先用广播赛事阶段，广播缺失时使用共享内存正赛类型与全场绿旗/黄旗。LMU 使用正赛会话类型与 mGamePhase，iRacing 使用会话 YAML 的 Race 类型与 SessionState。接口参考 [ACC 广播枚举](https://raw.githubusercontent.com/angel-git/acc-broadcasting/master/BroadcastingEnums.cs) 与 [iRacing SDK 定义](https://raw.githubusercontent.com/vipoo/irsdk/master/irsdk_defines.h)。

自动化在主程序运行、选中游戏且驾驶遥测有效时执行。按游戏保存触发条件和有序动作，定时任务按有效驾驶时间累计，语音问答优先，多个规则依次排队。每项动作执行时读取当前数据，排队超过 30 秒的过期事件丢弃。关闭规则或删除规则会移除对应等待任务。

本次验证使用构造的数据帧、游戏专属演示和桌面窗口测试，覆盖轮位、单位、玩家匹配、暂停/回放、过期读数、启动锁定与切换游戏。真实驾驶中的 HUD 数值仍待逐项对照。
